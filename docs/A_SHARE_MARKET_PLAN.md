# A 股整体市场实施计划

## 第 11-14 天：A 股整体市场数据闭环

目标：跑通上证指数全部成分股行情。第一版使用 `000001` 上证指数成分股作为股票池，并以上证指数本身作为基准。

任务：

1. 完成 `a_share_market_prices.py`。
2. 自动获取上证指数全部成分股。
3. 拉取历史日线，先用 `--limit 50` 做小样本验收，再全量拉取。
4. 计算价格特征。
5. 完成 A 股整体市场风险状态判断。

验收标准：

1. `prices_daily` 中有 `A_STOCK_%` 成分股数据和 `A_INDEX_000001` 基准数据。
2. 老成分股有 2 年以上历史数据，新上市或新纳入成分股允许历史较短，但需要在策略中被过滤或降权。
3. 能输出 `A-share market risk_on / neutral / risk_off`。

## 第 15-18 天：A_Share_Market_Score 和回测

目标：完成上证指数成分股第一版评分和周频选股回测。

任务：

1. 写 `a_share_market_scoring.py`。
2. 写 `a_share_rotation.py`。
3. 写 A 股整体市场回测。
4. 与上证指数基准对比。
5. 加入交易成本。

验收标准：

1. 输出 `A_Share_Market_Score`。
2. 输出每周 Top N 成分股目标仓位，第一版默认 Top 30、单票不超过 3%。
3. 输出策略净值。
4. 输出最大回撤。
5. 输出与基准对比结果。

## 第 19-22 天：上证成分股宽度 + 资金面代理

目标：加入能解释 A 股整体市场状态的横截面和资金面数据。

任务：

1. 写市场宽度采集模块。
2. 统计上证成分股上涨家数、下跌家数、涨跌停数量。
3. 计算上证成分股成交额变化。
4. 计算成分股站上均线的数量占比。
5. 计算北向资金、融资余额等可获取资金面代理数据。
6. 合并到 `breadth_proxy` 和 `liquidity_proxy`。

验收标准：

每日能回答：

1. 上证成分股是普涨、分化还是普跌？
2. 哪些成分股相对强？
3. 成交额是否放大或萎缩？
4. 风险状态对应哪些市场证据？

## 第 23-25 天：Dashboard

目标：完成可视化面板。

任务：

1. 写 Streamlit 首页。
2. 显示今日信号。
3. 显示上证指数成分股评分表。
4. 显示 Crypto 评分表。
5. 显示组合净值。
6. 显示风险警报。

验收标准：

```powershell
streamlit run src/dashboard/app.py
```

浏览器能看到：

1. 今日信号。
2. 上证指数成分股评分。
3. Crypto 评分。
4. 风险状态。
5. 回测净值曲线。

## 第 26-28 天：Dry-run 和手工模拟

目标：进入模拟交易阶段。

任务：

1. 配置 Freqtrade dry-run。
2. Crypto 运行 dry-run。
3. 上证指数成分股策略生成人工订单表。
4. 每日保存交易日志。
5. 检查是否超仓位。

验收标准：

连续运行 3 天：

1. 不重复下单。
2. 不超仓位。
3. 不买排除资产。
4. 每个信号都有原因。

## 第 29-30 天：复盘和 v0.2 规划

目标：形成 v0.1 复盘报告。

任务：

1. 检查 A 股和 Crypto 数据缺失。
2. 检查是否有前视偏差。
3. 检查交易成本影响。
4. 检查策略换手率。
5. 检查回撤是否可接受。
6. 规划 v0.2。

验收标准：

输出 v0.1 复盘报告：

1. 哪些模块已经稳定。
2. 哪些数据质量差。
3. 哪些因子有效。
4. 哪些规则要删除。
5. v0.2 要加入哪些功能。
